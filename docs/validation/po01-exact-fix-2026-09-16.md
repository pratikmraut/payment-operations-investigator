# PO01 exact-reference source correction, 16 September 2026

The supplied exact FCR request correctly omits `inquiryDate` and `recordCount`, as required by the reviewed FLEXCUBE wrapper. The bank response reports error 3403 and replyCode 99. This is an upstream application failure; the website must not import it as a successful inquiry or substitute cached data.

Read-only source review identified a concrete defect in `PkBaNEFTDiscoveryInquiry.setInputParameters`: nullable `Integer recordCount` was passed to primitive-int parameter binding and debug overloads. Java unboxes the missing value before the method executes. Fixing the SQL binder alone still leaves the debug call failing.

The correction binds SQL NUMERIC null when no record count is supplied, retains the integer binder for date-list counts, and uses the nullable String debug overload. No request field is invented and no database package change is required for this defect.

## Validation and application

Original exact FCR/UTR inputs reproduce the null-unboxing failure. The binder-only control reproduces the remaining debug failure. The corrected copy passes **42 assertions** across exact FCR, exact UTR and list counts 1, 20 and 200, including parameter positions and nullable date/count binding.

This isolated harness is not a compile against the complete bank classpath, an Oracle execution, or proof that the deployed binary matches the reviewed source. It establishes the local Java defect and the corrected binding behavior.
