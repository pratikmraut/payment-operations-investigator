# Dynamic UAT Q&A: local validation, 13 September 2026

**Result: dynamic integration completed; final semantic review failed.** The feature is experimental and must not be presented as a verified payment diagnosis.

The new website route accepts an analyst's own question over a private FCR export snapshot. It calls the local model and displays newly generated prose, cited claims, unknowns, read-only next checks and inference provenance. The offline payment Q&A report is not supplied to this model. Failed generation does not substitute a prepared answer.

## Actual model observations

Two small original synthetic controls used the same question with different amounts and raw states. The model returned the changed values, with two distinct generated answers and one real model invocation each. These development controls establish input-sensitive generation for those records; they are not an accuracy evaluation over bank data.

The first completed full-export history answer contained a wrong conversion into minutes and seconds and unsupported speculation. A later history retest correctly reported the changed field and exact formatted interval after generic computed comparisons were supplied. Independent source review still found imprecise limitation citations, event-versus-timestamp wording and unhelpful identifier-only next checks.

The first beneficiary question submitted through the browser completed, but its answer was semantically wrong: it decoded one status using another field's domain and turned missing proof into a negative outcome. The original answer is preserved. Subsequent changes explicitly scope source definitions to table columns, represent unmapped fields separately, distinguish unknown from false, and require readable next checks. These are reusable source and prompt constraints, not saved answers for one payment.

The smaller model's next warm retest correctly retained the unmapped field and produced readable checks, but still asserted a negative credit outcome and overinterpreted a queue-stage label. It therefore failed semantic review. The installed larger model is compared on the same source bundle and prompt through a UAT-only model override; the original case model configuration is preserved.

That larger-model comparison also failed: its cited claims did not establish the outcome, but the extra prose summary asserted a negative result. The final design removes separate summary generation. The model writes new cited claims for the question, and the service joins those exact texts without adding conclusions; Java and React reject inconsistent compositions. Old free-prose summaries remain preserved and labeled separately. This prevents a summary from adding an assertion outside the generated claim list, while leaving factual review of the claims necessary.

Cold CPU attempts have exceeded both the initial three-minute timeout and the later six-minute bound. A warm identical history retry completed in about 171 seconds. This does not establish cold-start reliability or a response-time guarantee. The [failure receipt](uat-qa-initial-failure.json) preserves failed attempts and semantic defects; successful retries do not erase them.

## Final browser result

The final claim-only request completed on the website using `qwen3:8b`: one actual model call, 6,487 input tokens, 453 output tokens and 270.721 seconds. Its initial cold attempt timed out; the completed result was an unchanged warm retry. The answer is saved with `answerComposition="joined-model-claims"`. Exact source objects, the canonical persisted request hash and the paragraph join were checked successfully. Earlier free-prose summaries remain preserved and distinctly labeled.

Factual review **failed**. Three claims correctly described an unmapped status and blank fields in the payment export. Two further claims incorrectly attributed those fields to a different source record where they are absent. An uncertainty statement also assigned the message-status value to separate transaction-status fields whose recorded values differ. The response did not directly establish the requested outcome. Its suggested follow-up evidence checks were more useful, but they do not repair the incorrect claims.

Removing separate summary generation stopped the displayed answer from adding a new assertion outside its claim list. It did not make that claim list factually reliable. Source membership alone is insufficient for payment analysis; further work needs reliable field-level grounding and independent evaluation before this extension can be trusted. No success or failure of the actual payment was established by these exports or model experiments.

The final [machine-readable receipt](uat-qa-2026-09-13.json), [history compatibility check](uat-qa-history-compatibility.json) and [preserved failures](uat-qa-initial-failure.json) record the exact scope. Full private source records and generated text are intentionally excluded from this public report.

## What the evidence establishes

This is an implemented local model integration with real inference and inspectable provenance. Its response validator establishes shape, bounded fields and exact source membership. It does not prove that every generated assertion follows from the sources. The reviewed samples are small development checks, not an independent accuracy benchmark or permission to act on payments.

The page consumes local exported records; no bank database/API connection, payment execution or complete beneficiary-credit feed was added. See [the setup, source contract and flow](../UAT_MODEL_QA.md).
