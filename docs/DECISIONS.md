# Architecture decision log

## ADR-023: Give local UAT inference a separate bounded wait

On 13 September 2026 the user's short OBPM-acceptance question failed before the CPU model finished reading its supplied evidence. The 360-second provider timeout was shorter than the observed cold input processing plus generation. The optional UAT deployment now permits a 900-second provider read, with a dedicated 930-second Java deadline and 960-second UAT proxy wait. Other case deadlines remain separate. Explicit model retention reduces repeated loading between nearby questions without caching generated answers.

Transport timeouts and local model-lock contention have distinct machine codes and safe browser guidance. The page shows measured elapsed waiting time; it does not claim a completion percentage. This remains a synchronous local workflow. A resumable background job would be a separate architecture change, not an implied capability of a longer HTTP wait. Source records, prompts and output validation are unchanged. The [repair validation](validation/uat-qa-timeout-fix-2026-09-13.md) records component and live evidence separately from factual model quality.

## ADR-013: Model generates one finding; rules own the public assessment
Implemented, tested and deployed with [108 worker tests](validation/worker-tests-108-pre-observed-context.json) and [31 web tests](validation/frontend-tests-31-pre-knowledge-health.json); v3 replay checks passed, but its first actual live finding was rejected for unqualified no-action wording. [Full-synthesis v2](validation/live-acceptance-v2-results.json) accepted a supported financial-only explanation for CASE-1002, but rejected CASE-1003's ambiguous “payment ... resolved without further action” wording. It failed the complete acceptance run despite four completed provider calls. More prompting and a narrow phrase gate did not establish reliable full-summary wording.

Limit synthesis to one cited evidence finding. The deterministic assessment supplies outcome, public summary, confidence, missingEvidence and proposal. Retain actual Ollama tool planning. For insufficient evidence, skip finding synthesis after the real planner call, recording one actual call rather than two. Preserve public API fields and historical results. Implemented `synthesisScope="finding-only"` or `"skipped-insufficient-evidence"` and `assessmentSource="deterministic-evidence-rules"`, with visible UI provenance and explicit historical/unknown handling.

This reduces the model-authored surface without pretending that generated evidence prose is guaranteed correct. Citation identity and semantic support still need separate checks. A smaller prompt or fewer calls is not a measured latency improvement; the component tests and deployment are complete, but v3 produced a rejected first finding despite valid links. New accepted/rejected results and actual call usage must be recorded before claiming runtime benefit. This design does not change money authority, authorization or independent review. The later [Java planner-only probe](validation/live-planner-only-java-4b.json) verified CASE-1041 through nginx/Java with one real call, skipped synthesis, no findings and rule-owned REQUEST_EVIDENCE in 34.979 seconds. The generic missing-evidence text remains a product limitation, not a concrete operational checklist.

## ADR-019: Align ledger semantics across Java and the worker

Java correction tested and deployed: [35 tests](validation/java-container-tests.json), image `f2b77ca3`, with 18 source files matching its build receipt. The final [worker198 receipt](validation/worker-tests-198-pre-selection-priority.json) confirms the defensive behavior below and image `90077f26` is built; [V6 deployment](validation/runtime-v6-4b.json) and [replay HTTP17](validation/acceptance-compose-replay-v6.json) are verified; [final model-enabled Java/reviewer acceptance](validation/acceptance-compose-ollama-v6b.json) subsequently passed 17 checks. Preserve [Java30 before alignment](validation/java-container-tests-30-pre-ledger-alignment.json). Review found that the worker recognized REFUND_POSTED while Java totaled only REFUND, allowing a refund-entry count with a zero authoritative refund total and a false mismatch. The authoritative validMoney flag also replaced the worker's own sign checks. These are deterministic interpretation defects, separate from model selection or wording.

The [Java calculation](../services/api/src/main/java/dev/pratik/poi/MoneyFacts.java) now normalizes type/status codes with Locale.ROOT uppercase and dot/hyphen-to-underscore conversion. CAPTURE, PAYMENT_CAPTURED and SALE require strictly positive amounts; REFUND and REFUND_POSTED require strictly negative amounts. Zero or the opposite sign is 422 INVALID_AMOUNT. FEE is non-positive, with zero allowed; a positive fee is invalid. Other signed types such as ADJUSTMENT remain part of the signed net without those capture/refund/fee predicates. Currency, integer-range and overflow checks remain in force.

Java still owns the totals and capture count. Blank, UNKNOWN or UNAVAILABLE provider status makes payout/discrepancy unavailable and null, even if a numeric zero was supplied. Availability is not inferred from that zero.

The [worker settlement check](../services/investigator/investigator/evidence.py) now retains its visible-ledger sign/currency validation and compares declared Java capture total, refund total, capture count, ledger net, provider payout, discrepancy and availability with the same snapshot. It also requires validMoney=true in the case currency. A contradiction adds specific money issues and produces insufficient evidence/REQUEST_EVIDENCE; it does not silently substitute a local total or render an invalid amount as an accepted catalog fact. Refund tools expose a ledger refund total only when the shared settlement validation succeeds. Recomputing for consistency does not transfer monetary authority away from Java.

Java35 is a completed build/test result, not proof of the entire corrected stack. The final 198-test worker and 35-test Java receipts cover aliases, posting signs, fees, signed adjustments, unavailable provider zeros and authoritative consistency. [Deployment](validation/runtime-v6-4b.json), [HTTP17](validation/acceptance-compose-replay-v6.json) and [adversarial16](validation/adversarial-replay-v6.json) confirm the recorded replay workflow; the first live fact-selection sample is recorded separately, and [V6b Java/model integration](validation/acceptance-compose-ollama-v6b.json) subsequently passed. The [intermediate 167-test receipt](validation/worker-tests-167-pre-money-boundary.json) predates the alias/FEE/consistency changes and must not be presented as final validation. Earlier Java30 and worker receipts remain evidence for their recorded revisions.

The first [V6 live six-family sample](validation/evaluation-ollama-development-v6.json) subsequently accepted six responses/11 calls with unchanged source, but three of five selection results omitted the available primary exception fact. Timeout, duplicate and ordering cases selected generic status plus success occurrence. Refund selected relevant discrepancy/refund facts; failure selected relevant status/event facts but omitted capture absence. Planner-only uncertainty is not a selection success. This supports ADR-017's distinction between output integrity and selection usefulness; it is not a model-prose accuracy result. The prompt-priority correction is implemented/deployed under ADR-020; its separately named V6b execution is preserved without changing this original sample.

## ADR-021: Generate UAT answers from private source snapshots

The user requested dynamic model-written website answers over their supplied FCR function exports. The original synthetic case workflow's catalogued fact selection cannot satisfy that request. A separate UAT question workspace therefore passes a session-authorized, versioned document bundle to a LangGraph retrieve/generate/validate graph and LangChain ChatOllama. There is no transaction-specific answer catalogue and the earlier offline Q&A report is not model context. Domain notes contain sourced field definitions, possible execution paths and interpretation limitations.

Java owns tenant access, strict request/bundle validation, canonical content hashes, stale-evidence checks and private result persistence. The worker keeps all small-collection evidence and source notes, ranks knowledge lexically, invokes the local model and validates output structure and exact citation membership. It cannot prove semantic entailment. Free prose remains a model hypothesis requiring review, not an authoritative payment outcome or a case recovery command. Unknown evidence can be explained dynamically without falsely classifying it as the demo's ECA timeout.

UAT inputs and full outputs remain in ignored local directories, with external tracing disabled for this graph. Failed/truncated/uncited answers are not replaced by prepared text. Questions are independent over the selected snapshot; history is displayed with evidence versions. A separate bounded UAT timeout and documents-first prompt order address observed CPU latency while preserving the original flow's timeout. [The feature guide](UAT_MODEL_QA.md) and dated validation distinguish implementation, actual model execution, failed attempts and the limited reviewed sample.

## ADR-022: Display newly generated UAT claims without a second summary

Live tests with both installed local models produced an unsupported negative outcome in the free-prose summary while their cited claims retained uncertainty. Stronger instructions and explicit field domains improved some claims but did not eliminate that summary contradiction. Preserve these failures in their original receipts.

The current model schema therefore generates only `claims`, `unknowns` and `nextChecks`. It cannot return an extra `answer` field. The worker's public `answer` is the exact ordered claim texts joined with two newlines, labeled `answerComposition="joined-model-claims"`. Java and React verify that composition for new responses. React displays each generated claim once with its citations and places uncertainty near the question. Historical free-prose responses remain readable and explicitly labeled; they are not rewritten to appear corrected.

The model still writes new claims for each question and authorized input. There is no fixed sentence catalog, prepared payment answer or post-processing rewrite of its claims. Exact composition prevents the display from adding another assertion beyond those claims; it does not prove the claims themselves are true. Source membership, explicit field domains and formatted arithmetic remain useful constraints alongside human factual review. The optional UAT model selector permits a larger installed local model without changing the synthetic case model.
