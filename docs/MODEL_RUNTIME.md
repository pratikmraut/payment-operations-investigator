The final local runtime uses V6b with Qwen3 4B, lexical retrieval and five running project services: [runtime-final](validation/runtime-final.json). Java35, worker198 and UI34 tests, [replay17](validation/acceptance-compose-replay-v6b.json), [adversarial16](validation/adversarial-replay-v6b.json), [replay30](validation/evaluation-replay-test-v6b.json), [live Java17](validation/acceptance-compose-ollama-v6b.json), [selection review](validation/v6b-fact-selection-review.md), [planner/hybrid review](validation/v6b-live-planner-hybrid-review.json), [browser14](validation/frontend-browser-v6b.json), [cached startup](validation/start-with-ai-v6b.json) and [fresh-volume rehearsal](validation/rehearsal-compose-v6b.json) are recorded. These are bounded synthetic-data results; the model selects facts and the service renders wording/links. The main editable delivery is the project folder and its VS Code workspace. Earlier ZIP verification is preserved in `docs/validation/package-history/latest-release.json`; the user requested removal of redundant packages. See [source-folder delivery](validation/source-folder-delivery.json).

The application has deterministic replay and explicit Ollama modes. Replay executes the evidence workflow but does not invoke a language model. A successful replay test is not an LLM accuracy result.

Initial local selection: Qwen3 4B Instruct (about 2.5 GB download) through Ollama; nomic-embed-text v1.5 (about 274 MB) for optional real embedding retrieval. Both models are downloaded in the dedicated local volume. The observed runtime uses CPU inference; no GPU acceleration has been verified.

## Per-request CPU thread experiment
Read-only inspection found eight available CPUs, eight automatically selected inference threads, no container CPU quota/throttling, and no observed OOM events. The cause of slow decoding was not established by those reads.

A bounded ordered pair of actual requests used identical neutral input, 48 output tokens, temperature zero and a 4096-token context. Both returned identical text at the token cap. Eight threads decoded at 1.4448 tokens/second; four threads decoded at 14.399 tokens/second. Load and prompt processing were measured separately. This single pair is an exploratory result with order/cache/host effects, not a general performance guarantee. See [thread experiment](validation/model-thread-probe.json).

The project now explicitly requests four model threads through POI_MODEL_THREADS for a full-case test. This is a request option, not a machine-wide CPU or GPU configuration change. A complete live investigation must still pass its schema, reference, money and review checks. The value can be overridden for another host; four is not claimed as universally optimal. [Ollama 0.34.0 request options](https://github.com/ollama/ollama/blob/v0.34.0/api/types.go).
